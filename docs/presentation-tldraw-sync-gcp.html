Key Design Decision: Consistent Hashing

NGINX routes requests by URI hash, ensuring all users in the same room connect to the same pod. When pods scale, the two-phase handover protocol safely migrates rooms.

Two-Phase Coordinated Handover

When pods scale, the hash ring changes and rooms need to migrate. The two-phase protocol ensures users are only disconnected after the new owner is ready.

Why Two-Phase?

Problem: Single-phase handover closes user connections before the new pod is ready. If the new pod is slow or crashes, users get stuck in retry loops.

Solution: Wait for "ready" signal before disconnecting users.

Phase 1: Lock Transfer

  1. Pod C fails to acquire lock (Pod A owns it)
  2. Pod C subscribes to handover-lock-released:{roomId}
  3. Pod C publishes request to room-handover
  4. Pod A saves state to GCS
  5. Pod A releases lock and signals

Phase 2: Ready Confirmation

  1. Pod C acquires lock
  2. Pod C loads state from GCS
  3. Pod C signals handover-ready:{roomId}
  4. Pod A receives signal, NOW closes sockets (1013)
  5. Users reconnect to Pod C (ready!)

Redis Pub/Sub Channels

Channel Direction Purpose
room-handover Pod C → Pod A Request room release
handover-lock-released:{roomId} Pod A → Pod C Lock is free, acquire now
handover-ready:{roomId} Pod C → Pod A Ready to serve, close your sockets

Users stay connected to Pod A until step 9. They only disconnect when Pod C is fully ready to serve them. This eliminates the "retry loop" problem of single-phase handover.

To Scale Beyond 7,000 Connections

1. Increase NGINX Ingress Replicas

Scale from 5 to 10+ replicas. Each NGINX pod handles ~1,400 connections.

2. Use Larger Node Types

Upgrade from e2-medium to e2-standard-4 or larger for more CPU/memory per node.

3. Tune NGINX Worker Connections

Increase worker-connections in NGINX ConfigMap (default: 1024 → 65536).

4. Add More Nodes

Scale node pool from 3 to 5+ nodes for better pod distribution.

Code Reference: Connection Flow

1. WebSocket Upgrade & Keep-Alive

// src/index.ts - WebSocket upgrade handling
server.on("upgrade", (request, socket, head) => {
  const { pathname, searchParams } = new URL(request.url, `http://${request.headers.host}`);
  const roomMatch = pathname.match(/\/api\/connect\/(.*)/);
  const roomId = roomMatch?.[1];
  const sessionId = searchParams.get("sessionId");

  if (roomMatch && roomId && sessionId) {
    wss.handleUpgrade(request, socket, head, (ws) => {
      wss.emit("connection", ws, request, roomId, sessionId);
    });
  }
});

// Keep-alive ping to prevent GCP LB idle timeout (30s)
const PING_INTERVAL_MS = 25000;

wss.on("connection", (ws, request, roomId, sessionId) => {
  const pingInterval = setInterval(() => {
    if (ws.readyState === WebSocket.OPEN) ws.ping();
  }, PING_INTERVAL_MS);

  ws.on("close", () => clearInterval(pingInterval));
  roomManager.getOrCreateRoom(roomId, ws, sessionId);
});

2. Redis Lock Acquisition

// src/roomManager.ts - Distributed lock with SETNX
const LOCK_TIMEOUT_SEC = 10;
const lockKey = `lock:room:${roomId}`;

// Try to acquire lock (atomic operation)
const lockAcquired = await redisClient.set(lockKey, POD_NAME, {
  EX: LOCK_TIMEOUT_SEC,  // 10 second TTL
  NX: true,              // Only if Not eXists
});

if (lockAcquired) {
  // We own the room - start heartbeat to maintain lock
  const lockHeartbeat = setInterval(() => {
    redisClient.set(lockKey, POD_NAME, {
      EX: LOCK_TIMEOUT_SEC,
      XX: true,  // Only if eXists (we still own it)
    });
  }, HEARTBEAT_INTERVAL_MS);  // Every 5 seconds
}

Code Reference: Two-Phase Handover

3. Phase 1: Request & Release Lock

// Pod C (new target) - Request handover
const subscription = await this.subscribeToLockReleased(roomId);

await pubClient.publish("room-handover", JSON.stringify({
  roomId,
  targetPodId: POD_NAME,
}));

const lockReleased = await subscription.wait();  // Wait up to 5s

// Pod A (current owner) - Handle handover request
await subClient.subscribe("room-handover", async (message) => {
  const request = JSON.parse(message);
  if (this.activeRooms.has(request.roomId)) {
    await this.releaseRoom(request.roomId);
  }
});

4. Phase 2: Ready Signal & Migration

// Pod A - Release room and wait for ready signal
async releaseRoom(roomId) {
  // 1. Save state to GCS
  const snapshot = room.getCurrentSnapshot();
  await persistRoomSnapshot(roomId, snapshot);

  // 2. Release Redis lock
  await redisClient.del(`lock:room:${roomId}`);

  // 3. Signal lock released, then wait for ready
  await pubClient.publish(`handover-lock-released:${roomId}`, {...});
  const isReady = await this.waitForReadySignal(`handover-ready:${roomId}`);

  // 4. NOW close user connections (they'll reconnect to Pod C)
  for (const ws of sockets) {
    ws.close(1013, "Room migrated to another server, please reconnect");
  }
}

// Pod C - Acquire lock and signal ready
const { acquired, shouldSignalReady } = await this.acquireLockWithHandover(roomId);
if (acquired && shouldSignalReady) {
  await pubClient.publish(`handover-ready:${roomId}`, { newOwner: POD_NAME });
}

Code Reference: Persistence & Shutdown

5. GCS Persistence (Throttled)

// src/gcsStorage.ts - Room snapshot persistence
export async function persistRoomSnapshot(roomId: string, snapshot: RoomSnapshot) {
  const file = bucket.file(`rooms/${roomId}`);
  
  await retryOperation(async () => {
    await file.save(JSON.stringify(snapshot), {
      contentType: "application/json",
      resumable: false,
    });
  }, 3, 1000);  // 3 retries, exponential backoff
}

// src/roomManager.ts - Throttled saves on data change
const saveToGCSThrottled = throttle(() => {
  const snapshot = room.getCurrentSnapshot();
  if (snapshot) persistRoomSnapshot(roomId, snapshot);
}, THROTTLE_SAVE_MS);  // Max once per 10 seconds

room = new TLSocketRoom({
  schema,
  initialSnapshot: await fetchRoomSnapshot(roomId),
  onDataChange: () => saveToGCSThrottled(),
});

6. Graceful Shutdown

// src/roomManager.ts - Clean shutdown on SIGTERM
public async shutdown() {
  console.log(`Shutting down, saving ${this.activeRooms.size} rooms...`);
  
  for (const [roomId, room] of this.activeRooms) {
    // Stop heartbeat
    clearInterval(this.roomHeartbeats.get(roomId));
    
    // Save final snapshot
    const snapshot = room.getCurrentSnapshot();
    if (snapshot) await persistRoomSnapshot(roomId, snapshot);
    
    // Release lock immediately (so other pods can acquire)
    await redisClient.del(`lock:room:${roomId}`);
  }
  
  // Close all Redis connections
  await Promise.all([
    redisClient.quit(), subClient.quit(), 
    pubClient.quit(), handoverSubClient.quit()
  ]);
}
